Quattro proposte. Il nome attuale nel repository è Fluid Player.

Enfatizza il ruolo di chi dirige i flussi in sala, come in una regia.

02 · Online e offline

Il player può usare il cloud, oppure lavorare senza

  • Senza rete: riproduzione e regia usano solo ciò che è già sul dispositivo.
  • Con rete ma senza login: il player resta operativo; nessun accesso ai dati cloud dell’organizzazione.
  • Con rete e login: l’utente vede e sincronizza i dati del proprio tenant. La riproduzione resta sulla cache locale.
  • Se la rete cade dopo un sync, si continua offline sui dati già scaricati.

Core · host

Host fisico

Profilo della macchina. Non è il system logico (schermi / superfici).

  • CRUD del profilo device (id, piattaforma, modello, firmware).
  • Snapshot HW: CPU, RAM, storage, display / capability AV.
  • Identificativo univoco e monitoraggio sul cloud.
  • Comandi host: reboot, accensione/spegnimento del display, volume.
Fluid Next · requisito funzionale 11 / 27
‹ ›

Core · system

Sistema e suddivisione di una o più finestre in device e sottodevice

Dove i contenuti vanno in onda.

  • CRUD del system e degli schermi / superfici.
  • System Manager: quale system è attivo, elenco schermi.
  • Play / pause / stop in modo uniforme su ogni superficie.
  • Il device è una superficie: vi si possono visualizzare più contenuti sovrapposti (video, audio, immagini, HTML, PDF, flussi video acquisiti).
  • I device si possono annidare: un sistema a layer. Il contenuto di un device può oscurare o meno quelli sotto, in base alla posizione del layer.

Core · system · layer

Device annidati

Un device contiene altri device. Chi sta più in alto nel layer può coprire chi sta sotto.

Device A video a tutto schermo · layer di fondo
Device B HTML / overlay · layer intermedio
Device C ticker / logo · layer frontale
Layer 3 · Device C Primo piano: sempre visibile
Layer 2 · Device B Visibile dove C è trasparente; oscura A
Layer 1 · Device A Sfondo: oscurato da B e C

Core · auth

Identità e sessioni

Fonte di verità per credenziali e token.

  • CRUD di account, credenziali e associazione del device.
  • Login / logout verso Fluid Next; refresh e scadenza sessione.
  • Manager della sessione corrente e dell’ambito organizzazione (tenant).
  • Senza sessione valida il canale cloud resta chiuso.

Core · playlist / standalone

Contenuti in sequenza o singoli

  • CRUD playlist, item, timing, loop.
  • Playlist Manager: scheduler che invia a system la sequenza di contenuti da mostrare sui device.
  • Ogni playlist gira su un solo device. Più playlist possono essere associate e lanciate insieme.
  • CRUD dei contenuti standalone.
  • Standalone Manager: scheduler che decide quale standalone lanciare sul device.
  • Uno standalone gira su un singolo device. Più standalone possono essere associati insieme e lanciati nello stesso momento.

Core · external flows

Flussi AV esterni

Ingressi e uscite di regia, oltre ai file in cache.

  • Manager: quali flussi sono attivi in contemporanea.
  • Routing ingressi / uscite verso le superfici.
  • Play / pause / stop del singolo flusso (via system).

Core · settings

Configurazione locale

Un unico posto per le impostazioni globali e quelle dei singoli moduli.

  • CRUD delle impostazioni e dei preset.
  • Manager: definisce quale tipo di impostazione applicare sull’applicazione.
  • Estendibile dagli altri moduli: configurazioni globali e dei singoli moduli sono centralizzate.

Core · communication

Comunicazione

Layer di comunicazione astratto per i comandi che il software implementa. Il layer di definizione dei comandi si riutilizza per veicolare gli stessi comandi su canali diversi.

  • I moduli usano l’astrazione del comando per comunicare tra loro: non sono vincolati al canale, ma al comando.
  • Canali: rete, seriale, Unix socket.
